How nodes work
  1. Deploy this same worker code again under a new name: npx wrangler deploy --name vidlyte-node-1.
  2. Set the same HMAC_SECRET (and UPSTREAM_ALLOWLIST if you customised it) on that node.
  3. Paste its base URL above, e.g. https://vidlyte-node-1.you.workers.dev, and click Add Node.

No separate node build and no DNS changes. The primary gateway automatically orders registered nodes using the strategy above, retries the next node on failure, and cools a node down for 60 seconds after 3 failures. Visitors and webmasters only ever use your primary worker URL.

                01
                
Swarm Worker Nodes: Mechanics & Distribution

              

              
Why webmasters never see or hardcode worker nodes, and how transparent failover operates.

            

          


          

            

              
Q: Should I distribute the worker node URLs to webmasters or visitors?

              
NO. You distribute ONLY your primary gateway URL (e.g. https://vidlyte.workers.dev/embed/movie/550 or your custom domain https://embed.yourdomain.com/embed/...). Webmasters, partner sites, and visitors never see, touch, or hardcode swarm worker nodes.

            


            

              
Q: If I add 3–5 worker nodes, will redirects happen on their own? Will it look weird?

              
No redirects ever happen in the viewer's browser. Swarm nodes operate as Internal Edge Mesh Relays:
                
    
                  
  • The viewer's browser requests media segments directly from your primary gateway (e.g. /stream/chunk/vl_...).
    • 
                  
  • In the background, the primary gateway calls fetchWithSwarmFallback() across your registered worker nodes.
    • 
                  
  • If Worker Node 1 is slow or blocked by upstream CDN firewalls, the gateway immediately queries Worker Node 2 with a fast 1,500ms timeout.
    • 
                  
  • The media chunk is delivered back to the viewer with HTTP 200 without any browser redirect, URL change, or video stall.
    • 
                

              

            

          

        


        
        

          

            

              

                02
                
Player Fleet Domains: Purpose & Censorship Resilience

              

              
Why custom player URLs exist and how they prevent global service shutdowns.

            

          


          

            

              
ISP & Regional Censorship

              
Courts in regions like the UK, Italy, and India enforce DNS-level domain bans. If your primary domain gets flagged, swapping the primary domain in the Fleet tab restores playback across all webmasters without editing code.

            


            

              
Ad-Blocker Filter Evasion

              
Brave, uBlock Origin, and AdGuard maintain domain blocklists. Custom player fleet domains allow rotating embed URLs so player scripts load seamlessly for 100% of viewers.

            


            

              
Whitelabel CNAME Partners

              
Major streaming partners can point their own subdomain (e.g. player.partner.com) via CNAME to VidLyte. They get fully branded URLs while your sovereign edge handles the heavy streaming.

            

          

        


        
        

          

            

              

                03
                
Zero-Cost Persistence: Cloudflare Free-Tier Stack

              

              
How VidLyte stores configuration and tracks domain telemetry without paid external databases.

            

          


          

            

              

                
100k Reads/Day Free

                
Cloudflare KV Store

                
Stores runtime JSON configuration, monetization settings, registered swarm node lists, and player fleet domains. Reads are cached at the edge with sub-millisecond access.

              


              

                
5M Reads / 100k Writes Free

                
Cloudflare D1 SQL

                
Serverless SQLite database storing domain referer metrics, impression counts, and allowlist/blocklist flags. Free tier comfortably handles 100,000+ daily visitors.

              


              

                
Zero Cost / Infinite

                
In-Worker Memory LRU

                
Edge workers batch impressions in local RAM and sync periodically. This prevents write saturation and keeps operations well below free limits at $0.00/month.

              

            


            

              How Requesting Domains are Discovered: When an iframe loads, VidLyte inspects the incoming Referer and Origin HTTP headers. The hostname is extracted and recorded in the governance table. The administrator can click Block or Allow at any time to restrict hotlinking.
